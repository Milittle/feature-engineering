# 核验后的证据如何重塑特征评估方案 v0.3

**结论先行。** 经第二轮逐条对原文核验，「特征前置评估与生命周期管理」方案 v0.2 的主骨架可以保留：L1 快筛、L2 双代理消融、入模用优效检验、下线用非劣效检验（ADR-0004）、负对照校准。但有五处必须在 v0.3 改动。

第一，判定统计量与方差模型要改。ΔAUC 不适合当检验统计量，改用配对的逐样本 ΔLogLoss。CI 要同时计入验证集抽样方差和训练样本抽样方差。判定从三分改为四分区：优效 / 等效 / 有害 / 功效不足，并给每格报告 MDE。

第二，负对照要分粒度、与候选同构、数量足够，并用 OHDSI 式经验零分布做参数化校准。用户级候选的「ID 记忆」偏差要先在基线中吸收，校准只作兜底。

第三，泄漏与训推一致性改用基于「可得时间」的 PIT 断言加样本级逐值比对。5.2 的「一致率 ≥ 99.9%」**在任何一手来源中都找不到出处**，应按特征类型改为 A/A 噪声底校准的阈值。

第四，下线要做组级非劣效检验、相对固定锚点设累计预算，执行时用 Meta IEFF 式的渐隐，替代「停训观察」。

第五，生命周期拆成「特征定义」和「特征 × 模型用量」两层状态机。PSI 不再作为拒绝条件，只作风险标签。

核验也推翻了第一轮报告里的一批说法。最关键的几处：三篇「回测」论文都不是特征评估器；「0.1% 显著」出自 Google，Meta 论文写的门槛是 0.02%–0.05% NE；SHARK 的 70% 包含量化；IEFF 确属 Meta。业界至今**没有公开任何「特征级 gate 在历史 AB 上的 precision/recall」**，所以 R1 的冻结回测只能借用模型级评估器的协议，本方案要自己建立第一条基准。

## 一、冻结回测是 R1 唯一可信的真值通道，但公开基准只有模型级

**已核证据。** 能直接照搬的一手协议出自 2609.25408，它针对的是对话式 AI，不是特征，但协议本身通用 ([2609.25408](https://arxiv.org/pdf/2609.25408))。[已核原文] 的要点如下：

- 同一份版本化规格在两个按时间先后排列的队列上保持固定。原文："without refitting, row selection, or threshold tuning. The offline evaluations were completed before treatment exposure"。
- 开发期用 leave-one-experiment-out。
- 同一实验内的对比共享对照组，因此 bootstrap 按**整个实验**重采样，共 10,000 次。
- 真值取三值：线上 CI 下界 > 0 记 +1，上界 < 0 记 −1，其余记 0。离线预测按同样方式由离线区间给出三值。
- 指标：precision = #{p≠0 ∧ p=y}/#{p≠0}，recall = #{p≠0 ∧ p=y}/#{y≠0}，micro 与 macro F1，以及错向调用数。
- 论文明确反对只看相关系数，原因是相关系数会掩盖弃权、漏判和错向调用。

Amazon 的做法补上了二项口径：用 Wilson 区间报告一致率，同时给出「全部对」与「只取线上显著对」两种口径 ([Amazon SIGIR'23](https://cdn.amazon.science/ed/07/7766149e4f8d80e4572af86c353b/how-well-do-offline-metrics-predict-online-performance-of-product-ranking-models.pdf))。

2608.02345 提供了一个关键的噪声上限：**同一实验两次独立重复的符号复现率只有 0.69**，任何预测方法的方向一致率都应拿它和「总猜正向」(0.57) 来比较 ([2608.02345](https://arxiv.org/pdf/2608.02345))。

离线与线上之间的差距有一手诊断样例：DoorDash 在同一实验期里，新模型用**线上日志特征**时为 −1.80%，用**离线 join 特征**时为 +2.45%，两者之差 4.25% 正好对上 4.3% 的线上线下差距；根因是特征陈旧和缓存残留，修复后差距降到 0.76% ([DoorDash §8](https://arxiv.org/pdf/2502.10514))。Airbnb 也报告过离线 NDCG 约 +1%、线上却不显著的情况 ([Airbnb](https://arxiv.org/pdf/1810.09591))。

**「显著」门槛跨公司相差一个数量级，必须写明口径** [已核原文]：

离线收益换算成业务价值的一手锚点有：JD「每 1‰ 离线 AUC ≈ 600 万美元广告收入」，原文没有时间单位 ([CSCNN](https://arxiv.org/pdf/2006.10337))；LLaTTE「0.25% NE ≈ 转化 +4.3%，年收入数亿美元量级」([LLaTTE](https://arxiv.org/pdf/2601.20083))；SIDE 的特征 RoI = (ΔNE_click + ΔNE_conv)/(2C)，其中 C 是以 kW 计的 logging 成本 ([SIDE](https://arxiv.org/pdf/2506.16698))。Google 2013 是目前最接近「特征准入 gate」的一手描述："New signals can be vetted by automatic testing and whitelisted for inclusion" ([Google 2013](https://research.google.com/pubs/archive/41159.pdf))。LinkedIn、Uber、Airbnb、字节、快手都**没有公开带数值的特征准入 gate**。

**v0.3 设计 [设计推断]。**

*7.x 评估器冻结回测（R1）。*

1. 每个评估器版本打版本号后冻结，版本内容包括代理超参、δ_min、Δ_eq、Δ_NI、各层经验零分布参数、斜率 b。
2. 只用冻结**之后**才开始 AB 的特征做前向验证。第 8 章 #12 的历史集只用于开发，开发时用 leave-one-experiment-out。
3. 线上真值 y 按线上 CI 取三值。L2 的四分区结论映射为离线预测 p：优效 → +1，有害 → −1，等效或功效不足 → 0。
4. 报告以下指标：precision、recall、micro 与 macro F1、错向调用数、方向一致率（带 Wilson 95% CI）、代理 Δ 与线上 Δ 的 Spearman 相关。对照基线有两个：「总猜正向」，以及按每个历史 AB 的 z 值估出的复现上限 Φ(z)²+Φ(−z)²。同一实验内的多个特征按实验整体做 bootstrap。

*样本量。* 真实一致率为 0.8 时，Wilson 区间随 n 的变化如下：n=20 时为 [0.58, 0.92]，n=50 时为 [0.67, 0.89]，n=114 时为 [0.72, 0.86]。据此分两档：

- V1 只要求 **10–20 个历史特征的「诊断性回测」**，验收条件是「错向调用 ≤ 1，并逐条做三桶归因」，不对一致率设硬线；
- **≥ 50 个前向样本**之后，才做「验收性回测」，要求一致率的 Wilson 下界高于 0.57。

*离线-线上差距诊断。* 照 DoorDash 的做法：影子期在同一时段分别用 logged 特征和 backfilled 特征评估同一个模型，两者的差值就是「数据通路差距」。按特征选择 join offset（例如 −2d、−3d），对齐线上延迟。

*R13 业务门槛：*

```
b̂      = 无截距加权回归：Δ_online,i ≈ b · Δ_proxy,i，权重 = 1/线上 CI 宽度（2609.25408 口径）
          b 必须用「代理 Δ」去回归，不可套用 JD 或 Meta 的生产模型汇率
δ_biz  = (C_feature_日 × 365 + C_AB) / (b̂ × 单位指标年价值)
δ_min  = max(δ_stat, δ_biz)            # δ_stat 默认 0，由负对照校准
ROI    = b̂ × Δ_proxy × 单位价值 / C_feature   # 报告字段，对齐 SIDE
```

b̂ 要同时报告 CI。历史点不够时，按 ML Test Score Model 2 的做法，用「故意劣化的模型」跑小流量 AB 补点 ([ML Test Score](https://research.google.com/pubs/archive/aad9f93b86b7addfea4c419b9100c6cdd26cacea.pdf))。

## 二、ΔLogLoss 作检验量、总方差入 CI、四分区判定：L2 统计协议

**已核证据。**

- Pepe 等证明，各类「无性能改进」的零假设等价于 H0: P(D|X,Y)=P(D|X)。基于 ΔAUC 的检验在全数据上 "unacceptably conservative"（模拟中 size < 0.005），似然比检验 (LRT) 渐近最有功效 ([Pepe 2013](https://pmc.ncbi.nlm.nih.gov/articles/PMC3625503/))。
- α-investing 的特征检验统计量就是 Δlog-likelihood ([Zhou 2006](https://jmlr.org/papers/volume7/zhou06a/zhou06a.pdf))。
- Chamandy 等：把记录当独立样本会低估方差。正确的可交换单元是 user，同一单元的所有数据片段在每个复本中必须同权，实现上**用单元 ID 的哈希为 Poisson 权重播种** ([Chamandy](https://static.googleusercontent.com/media/research.google.com/en//pubs/archive/43157.pdf))。
- Bouthillier 等：数据 bootstrap 是最大的方差源，初始化方差一般不到它的 50% ([2103.03098](https://arxiv.org/abs/2103.03098))。
- Lakens：NHST 与等效检验组合后有四种结论；真实效应为 0 时，等效检验的样本量为 n = 2(z_α + z_{β/2})²/Δ² ([Lakens 2017](https://pmc.ncbi.nlm.nih.gov/articles/PMC5502906/))。
- Spotify 的 IU/UI 校正规则见更正清单 #12 ([2402.11609](https://arxiv.org/abs/2402.11609))。
- BH 在任意相关下的版本是 BY，阈值为 αj/(m·Σ1/r) ([Johari](https://arxiv.org/abs/1512.04922))。
- SAFFRON 的默认 λ=1/2，W0<α，FDR 保证要求零假设 p 值相互独立 ([SAFFRON](https://arxiv.org/abs/1802.09098))。
- Deng 2021：随机二分的 1026 个实验中，按 p<0.1 选出的 168 个存在选择偏差；高斯先验的 EB 收缩等价于 James-Stein；先验厚尾时应改用混合先验（Ghidorah 在实证中最好） ([Deng 2021](https://www.microsoft.com/en-us/research/uploads/prod/2021/06/PostSelectionKDD2021.pdf))。

**对原型的判读 [设计推断]。** `feval/l2.py` 中 with/without 两侧共用同一权重矩阵，配对是对的。但 LightGBM 用了默认 subsample=1，`random_state` 固定，LR 又是凸优化，所以「seed 方差」约等于 0。v0.2 3.2.2 承认没有覆盖的训练随机性，实质上是**训练样本的抽样方差**。

**v0.3 设计：L2 协议（替换 3.2.2 判定段）[设计推断]。**

```
# 预注册（写入口径卡，批次开始后不得改）
α1=0.025（每个代理单侧）  q=0.10（批内 FDR）  β=0.20  B=2000
K=4（valid 日，间隔 ≥ 成熟期）  R 由 κ 校准决定  Δ_eq ≥ 3.24·SE_budget  Δ_NI ≤ δ_min（δ_min=0 时取 0.5·Δ_eq）
w_eval[u,b]  = Poisson(1)，种子 = hash(user_id, b)                # 所有候选、代理、窗口共享
w_train[u,r] = Poisson(1)，种子 = hash(user_id, "train", r)         # with/without 共用

# 单候选 j、代理 k
d_i       = logloss_base,i − logloss_exp,i                          # 逐样本增益，正为好
Δ̄_jk      = Σ_w n_w · mean_r Δ_{jkwr} / Σ n_w                       # 窗口合并（固定效应）
V_eval    = Var_b( 每个复本 b 内先对 r、w 求平均后的 Δ̄* )
s²_train  = mean_w Var_r(Δ_{jkwr})
SE²_jk    = V_eval + s²_train/R                                      # 训练窗口高度重叠，K_eff 保守取 1
# 经验校准（见第六节；该层零分布参数为 μ̂_g, σ̂_g；无探针时 μ̂=σ̂=0，退化为原规则）
Z_jk = (Δ̄_jk − μ̂_g − δ_min) / sqrt(σ̂_g² + SE²_jk) ;   p_jk = 1 − Φ(Z_jk)
p_j  = min(1, 2·min_k p_jk)                     # 双代理 OR 规则的 α 收回名义水平（或用 Simes）
优效集合 = BH(p_j, q)                            # 负对照显示 FDR 超标时改 BY 或 max-T 联合 bootstrap
MDE_jk = δ_min + μ̂_g + (z_{1−α1} + z_{1−β}) · sqrt(σ̂²+SE²)      # 乘子 2.80；按 Bonferroni 则为 3.08
```

**四分区判定。** 用 (1−2α1) 的 CI [L, U]，即 Δ 减去 μ̂ 后的 ± 1.96·√(σ̂²+SE²)：

| 结论 | 条件 | 去向（5.1） |
|---|---|---|
| 优效 | j ∈ BH 集合；可选附加条件：ΔAUC 下界 > δ_min_AUC | 进入联合确认 |
| 有害 | 两个代理的 U 都 < 0，且 ΔLogLoss 与 ΔAUC 都满足 | 已拒绝 |
| 等效（无实质增量） | 两个代理的 U 都 < Δ_eq | 已拒绝（「确认没有值得要的增益」） |
| 功效不足 | 其余情况 | **暂缓**：报告 MDE，以及所需用户数 n_c = n_c0·(SE_0/SE_target)²；最多复评 1 次，α 按 α/2 分配 |

几条配套规则：

- **R 的校准。** 用约 20 个候选（含正对照和负对照）跑 R=10，估计 κ = s²_train(R=1)/V_eval。若中位 κ < 0.1，生产用 R=1，SE 乘以 √(1+κ̂_90%)；否则生产用 R=3–5。增加评估数据**压不掉**训练端方差。
- **R3 选择偏差。** 采用时间隔离：L1 中用到 label 的指标只读 valid 日之前的训练日，PSI 继续用全部天数。若 L1 必须用最新数据，就按 user 哈希分出 20–30% 给 L1，L2 的 SE 会膨胀 1.12–1.20 倍。
- **联合确认。** 移到一个**确认日**上执行：确认日是更晚的一个成熟日，或 L2 用户哈希拆出的 30%。只做一次「F+S 对 F」的整体优效检验，再对 S 中每个成员做「去掉后非劣」的检验，非劣者视为冗余后剔除。
- **入选者的报告值与排序。** 用 EB 收缩：Δ^EB = μ̂ + τ̂²/(τ̂²+SE²)·(Δ̂ − μ̂)，τ̂² 用整批（含未入选）候选的矩估计。效应分布厚尾时，改用「0 点质量 + Laplace」的混合先验。收缩只用于报告和排序，不改变判定。
- **R9 滚动多窗。** 不采用评审清单建议的「3 窗至少 2 窗通过」。逐窗显著的通过概率是 power^K，任一窗显著则 α 约放大 K 倍，两种规则都有问题。改为合并检验，再报告三项不消耗 α 的稳定性诊断：I²、正号窗口占比 k⁺/K、留一窗口的 Δ̄ 范围。I² > 50% 或 k⁺/K < 2/3 时，结论标为「优效-不稳定」并转人工。
- **多目标的门控顺序。** 前一步不通过就停止，总 FWER ≤ α：
  1. 主目标在合并窗口上做 ΔLogLoss 优效检验（批内 BH）；声明 2 个主目标时，「任一优效」用 α/2。
  2. 主目标 ΔAUC 的业务门槛（可选）。
  3. 共享底座的次目标做非劣效检验，属于 IU 结构，α 不校正；power 按 1−β/(G+1) 设计，G=2 时乘子为 1.96+1.50=3.46。
  4. 稳定性诊断。
  5. 在确认日上做联合确认。
- **跨批多重比较。** 按周成批评估时，每批做 BH 即可。只有候选逐个到达、要逐个即时决策时，才用 SAFFRON(α=q, λ=0.5, W0=q/2, γ_j∝j^−1.6)。由于各候选共享 valid，只能期待 mFDR 水平的保证。

## 三、代理只宜粗筛准入，下线要组级非劣效加渐隐

**代理与生产模型 [已核原文]。**

- ERASE 在 4 个公开 CTR 数据集、4 种深度 backbone 上发现，GBDT、XGBoost、RF、Lasso 等浅层方法总体最差；在 Avazu 上，树方法因特征取值集中而失效 ([ERASE](https://arxiv.org/pdf/2403.12660))。
- 一项跨领域研究中，mean |SHAP| 排序的 Spearman 相关在树与树之间为 0.58–0.84，在 NN 与树之间只有 0.18–0.36。这是人脸识别场景，外推要谨慎 ([2607.04431](https://arxiv.org/pdf/2607.04431))。
- Cherepanova 等：当额外特征是纯噪声时，树重要性给 MLP 做特征选择与最好的方法持平；当额外特征是交互或 corrupted 类型时，树方法不如 Deep Lasso ([Cherepanova](https://arxiv.org/pdf/2311.05877))。
- 这些证据支持一个**不对称**用法：代理模型做「噪声或冗余」的下线初筛相对可信，做新特征准入只能当粗筛。方向与 ADR-0004 一致 [设计推断]。

**残差与热启动的工程事实 [已核原文]。**

- LightGBM 源码中，`BoostFromAverage` 只在没有 init_score 时才执行，所以**传入 init_score 后不会再从标签均值起步** ([gbdt.cpp](https://github.com/microsoft/LightGBM/blob/master/src/boosting/gbdt.cpp))。
- LPFS 在线上 checkpoint 上插入 gate 时，把 gate 函数除以初值，使初值为 1，保证插入前后模型输出不变 ([LPFS §4.8](https://arxiv.org/pdf/2206.00267))。
- SHARK 每删一个 embedding 表，就用小样本 fine-tune 恢复收敛 ([SHARK](https://arxiv.org/pdf/2308.09395))。
- **没有公开论文把「生产 logit 作 offset + 候选特征」当作标准准入方法报告过，也没有报告其与 AB 结果的相关性。**

**v0.3 设计：R2 [设计推断]。**

*(a) 代理基线快照。* 版本化的 `proxy_baseline@v`，内容包括：特征清单；代理无法使用的特征（序列、ID embedding、复杂交叉）的处理方式，默认用「用户历史目标统计 OOF 特征」替代 ID 记忆（见第六节）；超参与早停。快照版本写入 R16 评估指纹。

*(b) 线上分版本语义（6.5 接口补字段）。* `fetch(model_id, sample_window) -> {sample_key, logit, model_version, score_source∈{serving_log, replay}, feature_snapshot_ts, calibration_layer}`。

- **优先使用 serving 时刻落盘的 logit。**
- 如果只能回放，所用 checkpoint 的训练截止时间必须早于评估窗口起点；否则模型已经见过验证日的标签，残差增量会被低估。
- Platt 校准只在训练日上拟合；评估时同时传入 `eval_init_score`。

*(c) 残差的同构对照。* 「线上分 + 候选」对照的是「线上分 + 置换后的候选」，两者树数、正则相同，以扣除 boosting 自由度带来的纠偏收益。另跑一个「候选 + top-5 已有特征」版本，用来捕捉交互。

*(d) 合并规则（残差可得时与代理并列）：*

| 代理结论 | 残差结论 | 合并结论 |
|---|---|---|
| 优效 | 优效 | 强建议入模 |
| 优效 | 等效或功效不足 | 降为「暂缓」，标「疑似已被线上模型覆盖」 |
| 非优效 | 优效 | 建议入模（代理看不到的信息），进入 L3 热启动或直接进入 AB |
| 有害或等效 | 有害或等效 | 拒绝 |

*(e) L3 热启动通道。* 只对代理与残差结论冲突的特征触发：在生产 checkpoint 上加一个初值保证输出不变的 embedding 或 gate，用评估窗口之前的数据短训。

**下线流程 [已核原文]。**

- SHARK 每轮只删得分最低的 1 个表，删完 fine-tune 再重新打分，理由是信息耦合会让剩余特征的重要性发生变化。停止阈值是**相对原始基线的累计**精度阈值。注意原文「0.15% 显著」与「T_accuracy = 99.25%」两处数字自相矛盾 ([SHARK](https://arxiv.org/pdf/2308.09395))。
- 置换法会高估相关特征的重要性，应改用条件扰动或 drop-and-relearn ([Hooker](https://arxiv.org/pdf/1905.03151))。
- ERASE 的 Spearman 热图显示，门控类与 Permutation 类方法挑出的特征差异最大 ([ERASE](https://arxiv.org/pdf/2403.12660))。
- IEFF（Meta）的做法：
  - 在 serving 层按覆盖率渐隐，渐隐后的值同时用于推理和训练日志；
  - 生产速率 **1–2%/天**，边界实验与隐私类紧急下线用 5–10%/天，速率先经 QRT 验证；
  - 对 top 50 稀疏特征，置零造成 −0.83%，渐隐只有 −0.37%；**中段覆盖率（70%–40%）差距最大**；
  - 共 14 批、275 个特征，免去约 140 次重训，年基础设施成本约降 15%；
  - 作者自述的局限：强非线性交互特征仍可能需要显式重训 ([IEFF](https://arxiv.org/pdf/2605.00324))。
- 公开推荐系统文献中**没有**使用「非劣效」或「累计 margin 预算」术语的下线案例，这两个概念借自临床试验惯例。

**v0.3 设计：5.4、ADR-0004、R10 [设计推断]。**

1. **双通道初筛。** 生产模型内用 Taylor 分数（SHARK 式，几乎零成本），代理侧用 LOFO。两者都低才生成下线提案。
2. **组级联合确认。** 把候选下线集合按 |ρ| > 0.7 或互信息聚类，对**整组**做 drop-and-retrain 后的非劣效检验，要求两个代理都满足。批内按 SHARK 式贪心逐组执行：删一组 → 重训或热启动 → 重新打分 → 删下一组。
3. **累计预算。** 每个季度固定一个**锚点版本** M_anchor。每批下线后，当前模型相对锚点的 Δ 下界必须 > −ε_cum，其中 ε_cum 默认 = Δ_NI（≤ δ_min）。预算用完即停，防止多批「各自非劣、累计显著劣化」。
4. **执行。** 「停止进入新训练样本」改为 IEFF 式渐隐：默认 1.5%/天，约 67 天降到 0；覆盖率处于 70%–40% 时，监控频率加密到每日 NE 与业务指标双检；超过护栏自动暂停，回滚只需改配置。若模型没有日更或周更的循环训练，退回「停训 + 观察一个训练周期」。
5. **ADR-0004 补三条：** Δ_NI ≤ δ_min；ε 作用于整组；跨批使用累计预算。

## 四、可得时间 PIT 断言与样本级比对替代 99.9%

**已核证据。**

- PIT 语义在各平台一致：取「特征时间 ≤ 样本时间」的最新值，并受 TTL 限制。分歧在于「特征时间」取哪个时间：
  - Feast 只约束 event_timestamp，上界包含等号；created_timestamp 默认只用于去重，回填或修正的值可能穿越，`filter_by_created_timestamp=True` 可以修补 ([Feast](https://github.com/feast-dev/feast/blob/master/docs/getting-started/concepts/point-in-time-joins.md))。
  - Tecton 用 `_effective_timestamp`，定义为 "the earliest time the feature will be available in the online store"；批特征 = 物化开始时间 + data_delay ([Tecton](https://tecton-docs.pages.dev/docs/reading-feature-data/reading-feature-data-for-training/constructing-training-data))。
  - Azure 取窗口 [t − lookback, t − source_delay] 内的最新值，source_delay 默认 0；忽略它会让上线后的分数下降 ([Azure ML](https://learn.microsoft.com/en-us/azure/machine-learning/offline-retrieval-point-in-time-join-concepts))。
- ML Test Score Monitor 3：同一样本的特征值 "should be perfectly identical"，监控「有 skew 的特征数」和「每个 skew 特征的样本数」；原文称这项测试 "most important and least implemented" ([ML Test Score](https://research.google.com/pubs/archive/aad9f93b86b7addfea4c419b9100c6cdd26cacea.pdf))。
- Rules of ML：
  - #29：至少对一小部分样本落 serving 特征；
  - #34："Ten thousand examples is enough"；
  - #37：next-day 与线上之间 "should give you exactly the same result"，有差异 "probably indicates an engineering error" ([Rules of ML](https://developers.google.com/machine-learning/guides/rules-of-ml))。
- Data Validation 论文：time travel 是 feature skew 的一种机制；检测方法是 key-join 加逐特征比较；卡方检验在 1 亿样本、0.01% 噪声下 10 次误报 7 次，因此改用 d∞；Google Play 消除一个特征 skew 后安装率 +2% ([Breck 2019](https://mlsys.org/Conferences/2019/doc/2019/167.pdf))。
- TFDV `DetectFeatureSkew` 的输出字段包括 match/mismatch/base_only/test_only，diff_count = 三者之和；`float_round_ndigits` 控制数值容差 ([TFDV proto](https://github.com/tensorflow/data-validation/blob/master/tensorflow_data_validation/skew/protos/feature_skew_results.proto))。TFDV 文档里的 L∞ = 0.01 **只是示例** ([TFDV](https://www.tensorflow.org/tfx/data_validation/get_started))。
- Chronon 用线上 query log 替换 join 左表后离线重算，比较 mismatch/missing/extra/SMAPE；按 key 哈希抽样；原文 "100% consistency ... not always possible"，**不给阈值**；日更特征的不一致集中在午夜附近 ([Chronon](https://github.com/airbnb/chronon/blob/main/docs/source/test_deploy_serve/Online_Offline_Consistency.md))。
- 泄漏阈值唯一有出处的是 deepchecks 的默认值：train PPS ≥ **0.7**；|train PPS − test PPS| ≥ **0.2** 判 FAIL ([deepchecks](https://github.com/deepchecks/deepchecks/blob/main/deepchecks/tabular/checks/train_test_validation/feature_label_correlation_change.py))。Kaufman 等泄漏论文的检测方法清单本轮没能读到原文。

**v0.3 设计：R5 候选提交规范 [设计推断]。** 提交方提供 `(entity_key, value, event_ts, created_ts, avail_ts)`。

```
avail_ts = max(event_ts, created_ts, 批物化完成时刻 + data_delay)
join 条件：avail_ts ≤ sample_ts  且  sample_ts − avail_ts ≤ TTL；join 不到时为 null，并单独统计覆盖率
spine = 线上请求日志（request_id, entity, sample_ts）
```

**PIT 测试套件（3.1.1 与 5.2 #5「时点正确性（硬）」的实现）：**

| 编号 | 测试 | 判定 |
|---|---|---|
| P1 | 逐行断言 avail_ts ≤ sample_ts；窗口右端点 < sample_ts，且不含样本自身事件 | 违规行数 = 0（硬门槛） |
| P2 | 未来注入：向源表注入三类哨兵记录：event_ts > sample_ts；created_ts > sample_ts（模拟回填）；落在边界上的事件 | 哨兵命中 = 0（硬门槛） |
| P3 | logged 对 backfilled：影子期按 key 哈希抽样后逐值比较 | 见下方 S3 |
| P4 | 延迟平移：把 sample_ts 整体前移 Δ ∈ {声明的 data_delay, 1h, 1d}，重算单特征 AUC（即 R7 的「错一天」测试） | AUC 降幅超过同类健康特征的 P99 → 可得时间被低估 |
| P5 | 日快照对比精确 PIT | 差异大的特征在线上必须按快照语义服务 |
| P6 | null 率随「样本时间 − 特征时间」的分布 | 纳入 S3 的 missing 指标 |

**5.2 #6 改写（删除「≥ 99.9%」）：**

| 层 | 指标 | 起始阈值 |
|---|---|---|
| S1 schema | 名称、类型、取值域 | 0 容忍 |
| S2 分布 | 类别特征用 L∞；数值特征用 JSD（QUANTILES 直方图）或归一化 Wasserstein | L∞ 0.01–0.05；JSD 或 Wasserstein 0.1；0.3 只作宽松上限（BQML/Vertex 默认值） |
| S3 样本级 | exact_match_rate = match/(match+mismatch+base_only+test_only)、missing_rate、extra_rate、数值 SMAPE、序列编辑距离、join 失败率 | 确定性批特征：**exact_match = 100%**，任何 mismatch 都要逐条解释；实时、流式、日更特征：按 lag 对齐后，以同类在线健康特征 mismatch_rate 的 **P99** 为线 |
| S4 打分级 | 同一请求离线分与在线分的差 | \|Δscore\| < 1e-4（PAI-Rec 口径）的请求占比 |
| S5 效果级 | Rule #37 的三段差距 | next-day 与线上之间显著有差即判工程错误 |

S3 的样本量：每个特征至少 1 万个两侧都有 ID 的样本，并覆盖一个完整日周期（含午夜）。若仍要保留「99.9%」，文档必须注明它是**内部设定**的确定性特征下限，没有外部出处。

**L1「疑似泄漏」改为多信号（替换合成规则第 2 条），任一信号触发就转人工，并强制跑 P1 和 P2：**

1. L-a 绝对强度：PPS ≥ 0.7，或单特征 AUC、IV 超过该场景干净特征的 P99。原「IV > 0.5」降为「经验值，待校准」。
2. L-b 时间回落：随机切分与时间切分的 ΔPPS ≥ 0.2。
3. L-c 可得性：P1 或 P2 有违规。
4. L-d 延迟敏感：P4 判定不通过。
5. L-e 线上回落：影子期 logged 特征的单特征 AUC 低于离线回填 AUC。

**阈值校准：** 构造合成泄漏样本作为已知阳性，包括 label 加噪、窗口越过 sample_ts、用回填修正值替代原值；以已上线的干净特征作已知阴性。按 ROC 选阈值，目标是泄漏召回 ≥ 95%，同时干净特征误报 ≤ 5%。每季度用新确认的真阳性和假阳性更新一次。

## 五、两层状态机、Spotify 式 AB 规则、漂移降级为标签、成本入账

**已核证据。**

- 已核的特征平台都没有多状态的特征状态机。Tecton 的 `prevent_destroy` 只在 live workspace 生效，设在 Feature Service 上时会连带保护其依赖的 Feature View ([Tecton](https://docs.tecton.ai/docs/sdk-reference/feature-views/BatchFeatureView))。Hopsworks 只有可撤销的软废弃告警 ([Hopsworks](https://docs.hopsworks.ai/latest/user_guides/fs/feature_group/deprecation/))。Feast + MLflow 提供「改这个 feature view 会影响哪些模型」的反向索引 ([Feast MLflow](https://docs.feast.dev/master/reference/mlflow))。**没有任何平台把「特征 × 模型」做成带状态的一等实体**，v0.3 的这一设计没有直接先例。
- Spotify 的 Decision Rule 2：上线需同时满足四条——至少一个 success 指标显著优效；所有 guardrail 显著非劣；没有任何指标显著劣化；没有任何 quality 检验（如 SRM）拒绝。guardrail 的 α 不校正，β 要校正 ([Spotify](https://arxiv.org/pdf/2402.11609))。
- 广告场景必须把校准列为护栏。LinkedIn："Ads charging prices are linked to click-through rate (CTR) probabilities, making accurate calibration essential" ([LiRank](https://arxiv.org/pdf/2402.06859))。csAUC 指出 AUC 不反映 CTR×bid 的排序 ([csAUC](https://arxiv.org/abs/1904.10272))。
- 漂移不能当作效果下降的代理，三项一手证据方向一致：
  - VLDB 2024："not all data drifts lead to degradation"，主张只对有害漂移重训 ([PVLDB](https://www.vldb.org/pvldb/vol17/p3072-dong.pdf))；
  - NannyML 580 组实验：用漂移信号估计性能，效果还不如「假设性能恒定」的朴素基线；原文建议先估计性能，性能下降了再回头看漂移 ([HF blog](https://huggingface.co/blog/santiviquez/data-drift-estimate-model-performance))；
  - Vertex AI 的默认漂移阈值为 0.3，比较对象是相邻两次快照，并提供 SHAP 归因漂移监控 ([Vertex](https://docs.cloud.google.com/vertex-ai/docs/model-monitoring/overview))。
- ML Test Score Data 3 列出的成本要素有四项：推理延迟、RAM、上游数据依赖、预期不稳定性 ([ML Test Score](https://research.google.com/pubs/archive/aad9f93b86b7addfea4c419b9100c6cdd26cacea.pdf))。
- 阿里 FSCD 用 c_j = γ1·o_j + γ2·e_j + γ3·n_j（在线计算复杂度、embedding 维度、key 数）作为特征保留先验。原文指出，query/user 特征每次请求只算一次，item 特征的成本随候选数增长 ([FSCD](https://arxiv.org/pdf/2105.07706))。
- Databricks 的特征计费只到管道级 ([Databricks](https://docs.databricks.com/aws/en/machine-learning/feature-store/cost-management))。
- Sculley 指出：上游信号的「修复」也可能伤害下游模型，建议对信号做版本化副本 ([Sculley 2015](https://proceedings.neurips.cc/paper_files/paper/2015/file/86df7dcfd896fcaf2674f757a2463eba-Paper.pdf))。

**v0.3 设计：5.1（R6）[设计推断]。**

```
FeatureDefinition（特征实体，按 feature_id@version 区分）
  draft → registered → deprecated（软废弃，告警）→ archived
  进入 archived 的前置条件：反向索引中没有任何 active 状态的 Usage（对齐 prevent_destroy 语义）
  上游信号变更（包括「修复」）一律视为新 version，重新走评估

FeatureUsage（feature@version × model × 场景）
  candidate → offline_evaluated → shadow_logging → ab_testing → online
            → offboard_proposed → fading → removed

```

无法离线回填的实时特征，`shadow_logging` 排在 L2 之前，影子日志就是 L2 的数据来源（log-and-wait）。

**各阶段出口条件：**

- **shadow_logging 出口：**
  - S1 至 S3 达标（第四节）；
  - 取数 P99 延迟增量和超时率在预算内；
  - 线上覆盖率与离线评估口径一致；
  - 用落盘值重跑一次 L2，结论不变（R7）；
  - 时长 ≥ 7 天且覆盖一个完整周。这是推断，没有一手出处。
- **ab_testing 规则（R14）：**
  - success 指标：RPM、收入或 CTR/CVR，做优效检验；
  - guardrail（预先登记 NIM）：分切片 PCOC 或 ECE、P99 端到端延迟、超时率、广告主 ROI、负反馈率；
  - 所有指标同时做劣化检验；
  - quality：SRM；
  - power 按 1−β/(G+1) 设计。时长由护栏的功效反推（参考 Airbnb 的 StdErr < 0.8·t，[二手 InfoQ]），不固定天数。
- **离线段护栏（3.2.2 新增）：**
  - 主指标优效，且 ΔLogLoss 非劣（下界 > −Δ_NI）；
  - CVR、PLTV 等用于出价的目标，追加分桶校准偏差非劣。

**漂移处理（R8；3.1.3 与 5.2 #3）：**

- PSI 不再作为拒绝条件，改为 `stability_tag ∈ {stable, watch, drifting}`，仍按 0.1/0.25 分档，但标注「信用评分惯例，未校准」。
- 只有两类「伪漂移」直接阻断：一是数据质量问题，包括缺失率或默认值占比突变、常量化、线上线下不一致；二是时点泄漏。
- 被标为 drifting 的特征，L2 加做时间外推稳定性检验：K ≥ 4 个窗口的合并优效（沿用第二节协议，**不要求逐窗显著**），并且最差窗口的点估计 ≥ −Δ_NI、k⁺/K ≥ 3/4。这里调和了两份研究笔记的分歧：逐窗 CI 下界 > 0 会过度消耗功效。
- 5.2 #3「连续 7 天 PSI < 0.1」**删除**，由上面的检验与 shadow 一致性检查替代。
- 上线后的监控优先级：带标签的效果与分切片校准 > 重要性加权或归因漂移 > 原始 PSI（只用于定位原因）。
- 5.4 触发条件 4 中的「PSI 长期超标」，必须同时伴随效果或重要性下降才触发下线消融。

**成本账本（7.2 提前到 V1 收集，R13）：**

| 维度 | 字段 | 计量与分摊 |
|---|---|---|
| 离线计算 | 物化与回填作业的 CPU·h | 管道账单按产出列字节占比分摊 |
| 存储 | 离线表字节 × 保留期；在线 KV 字节 × 副本数 | 直接计量 |
| 模型侧 | embedding 参数量 n_j × e_j、显存 | 直接计量（FSCD 的 n、e） |
| 在线 | P99 取数延迟增量、单请求开销 | user 侧特征每请求算一次；item 侧特征 × 候选数（FSCD 的 o_j 思路） |

## 六、同构、足量、校准：负对照规则与用户 ID 记忆

**已核证据。**

- 置换 p 值的有限样本形式为 (1+#{T^(m) ≥ T})/(1+M) ([CPT](https://arxiv.org/abs/1807.05405))。
- Boruta 的做法：每轮超过 shadow 最大值记一次命中，零假设下命中概率为 0.5，对命中数做二项检验并加 Bonferroni，默认 pValue 为 0.01 ([Boruta.R](https://github.com/cran/Boruta/blob/master/R/Boruta.R))。
- Stoppiglia 的风险 r 是逐步累积的概率（类似 FWER 的停止规则），也可以改用多个探针实现的经验秩分布 ([Stoppiglia 2003](https://www.jmlr.org/papers/volume3/stoppiglia03a/stoppiglia03a.pdf))。
- NIPS 2003 特征选择挑战中，BER 第一名选中的特征里 **47.8% 是探针**：整体性能好不等于特征选择干净 ([NIPS 2003](https://proceedings.nips.cc/paper_files/paper/2004/file/5e751896e527c862bf67251a474b3819-Paper.pdf))。
- Winkler：可交换块分两种，只在块内置换，或整块互换 ([Winkler 2014](https://europepmc.org/article/PMC/PMC4010955))。
- CPT：离散条件变量下可以层内置换；**连续变量分箱后再层内置换就不再保证 I 类错误** ([CPT](https://arxiv.org/abs/1807.05405))。
- OHDSI 经验校准的模型：y_i ~ N(θ_i, τ_i²)，θ_i ~ N(μ, σ²)，用极大似然估计 μ、σ²；新估计的单侧 p 值基于 N(μ, σ²+τ²)。校准后负对照 p<0.05 的比例为 6%、11%、5%；「至少 54% 的 p<0.05 发现在校准后不再显著」 ([Schuemie 2014](https://europepmc.org/article/PMC/PMC4285234))。
- 校准的前提是负对照与目标假设可交换，并且要始终做留一法自检 ([Schuemie 2016](https://europepmc.org/article/PMC/PMC5108459))。代价是 II 类错误显著上升 ([Gruber 2016](https://europepmc.org/article/PMC/PMC5012943))。
- CI 校准需要靠注入合成的正对照 ([EmpiricalCalibration](https://cran.r-project.org/web/packages/EmpiricalCalibration/vignettes/EmpiricalCiCalibrationVignette.pdf))。
- CatBoost：取值全部唯一的类别特征配 greedy TS，训练集一刀就能完美分类，测试集只有 50%；LOO TS 仍然泄漏；ordered TS 可解 ([CatBoost](https://arxiv.org/abs/1706.09516))。
- GPBoost：LightGBM 能学到高基数组效应，对已有组的预测更好，对新组更差 ([GPBoost](https://arxiv.org/abs/2004.02653))。
- sklearn GroupKFold 用于检测「记住个体」式的过拟合 ([sklearn](https://scikit-learn.org/stable/modules/cross_validation.html#group-k-fold))。

**探针数量的推导 [设计推断，次序统计量]。** 若零候选与 N 个探针可交换，它超过第 k 大探针的边际误放率恰好是 k/(N+1)，而单批的实际误放率服从 Beta(k, N+1−k)：

| N | k | 名义误放率 | 单批实际误放率 90% 区间 |
|---|---|---|---|
| 3 | 1 | 25% | 1.7%–63% |
| 19 | 1 | 5% | 0.3%–14.6% |
| 99 | 5 | 5% | 2.0%–9.0% |
| 199 | 10 | 5% | 2.8%–7.8% |

mock 中每层每批只有 3 个探针，等价于名义误放率 25% 的 max 规则，这能解释 7.1 #9 中「观察」比例偏高的一部分。若要以 95% 置信保证单批误放 ≤ 5%，max 规则需要 N ≥ 59。

**v0.3 设计：第 8 章 #14（L1 阈值）。**

- 每层（行 / 用户×天 / 用户 / 交叉 / 序列）**N_L1 = 199** 个同构探针。L1 不训练模型，这些探针几乎没有成本。
- 拒绝与观察的边界 = max(0.005, 该层探针 AUC 偏移的 95% 分位)；观察与通过的边界 = max(0.02, 该层探针的 99.5% 分位)。IV 同理。
- 交叉候选每轮多达 500 个时，「通过」改用经验 p 值 (1+#)/(N+1) 加 BH(q=0.1)。此时 N 需达数千，L1 仍可负担。

**v0.3 设计：同构负对照（R11、#13）：**

| 候选类型 | 同构负对照 |
|---|---|
| 行级 | 全局置换 |
| 用户级（用户内常量） | 用户间整块置换 |
| 用户×天 | 默认同一天内跨用户置换；检验时间维增量时，改为同一用户内跨天置换 |
| 交叉 f(a,b) | **f(a′, b)**，a′ 是 a 在 b 的层内置换。b 连续时按 10 分位分箱，此时只是近似。廉价版 f(perm(a), b) 只保证基数和稀疏度同构 |
| 序列 | 用户间整段置换（检验内容）；换用该用户更早日期的快照（检验时点）；序列内打乱顺序（检验顺序） |
| 冗余型 | 每层 ≥ 5 个「基线特征 + 噪声」（落实 7.1 #6） |

R11 的 L1 改为检验「交叉相对两个父特征相加的模型的额外信息」，负对照用 f(a′, b)，比评审清单的「噪声 × 父特征」更严格。完整 knockoff 不适合本场景：knockoff+ 至少要选出 ⌈1/q⌉ 个特征才能报告发现，而且要对全部特征的联合分布建模。

**v0.3 设计：L2 经验校准（#8、7.1）。**

1. 每层、每代理、每批新增 **20 个**探针做消融，与同一管线配置下的近期批次合并，使累计 **≥ 50** 个。
2. 用极大似然拟合 (μ̂_g, σ̂_g)，判定公式见第二节的 Z_jk。μ̂ = σ̂ = 0 时退化为 v0.2 的规则，所以这是对现有判据的严格推广。
3. 留一法自检：该层探针的校准 p<0.05 比例应落在 [2%, 9%]，超出则该层标「校准不可信」，回退到人工加残差分析。
4. 每层注入 3 档正对照：shadow + λ·z(已知有效特征)，λ 分别使 ΔAUC 约为该层 τ 中位数的 1×、2×、4×。报告检出率曲线和 MDE（R4 的「分级正对照」）；最弱一档检出率 < 50% 时，报告中提示「本层功效不足」。
5. μ̂、σ̂ 超出近 10 批的 3σ 时，触发管线审查（等价于 A/A 检查）。
6. 若 R ≥ 3，候选「优效」的出现频率 ≥ 0.5 才最终建议入模。这只借用了去随机化 knockoff 的稳定化思想，不继承它的误差保证。
7. 管线配置一变，累计的探针就清空重来。

**v0.3 设计：用户 ID 记忆（#13）。**

- **主口径：** 两个代理的基线都加入「用户历史目标统计」：训练行用 5 折 OOF 或 ordered 计算，验证行用全部训练日，贝叶斯平滑先验强度为 20 次曝光。这样剩下的增量就是「超出用户固定效应」的部分，与线上带 ID embedding 的模型对齐。
- **兜底：** 用户级同构探针的经验校准（σ̂_user 会自动吸收残余的记忆奖励）。
- **最终裁决：** 残差分析可得时以它为准（mock 中残差判据下用户级探针误放 7%）。
- **诊断：** 每季度或管线变更时跑一次新用户 holdout（训练用户与验证用户不相交），确认加入 TS 之后 σ̂_user ≈ 0。
- **不采用**「只与同批用户级探针比较」作主判据。GPBoost 的结果表明记忆奖励的大小随组数与树参数变化，阈值会随批次漂移，还会把真实但弱的用户级特征一起压掉。

## Conclusion

第二轮核验带来的主要变化在于证据的性质，而不在设计方向。第一轮报告看起来「有先例」的地方，比如回测 F1、SIDE 的单特征增益、70% 存储节省、0.1% 显著，核验后要么场景不对，要么口径混在一起。业界真正公开的是**协议**（冻结前向验证、三值真值、Wilson 区间、IU/UI 校正、OHDSI 经验零分布、IEFF 渐隐），**不是特征级的阈值**。所以 v0.3 的每一个数字都应被看作「需要内部标定的参数」，而不是「对标业界的值」。正因为如此，评估器版本化、冻结回测和 μ̂/σ̂ 的批次监控，要排在任何具体阈值之前落地。

第二个认识是：v0.2 暴露的几处偏差，包括用户级探针误放、弱增量被成批判为「无显著」、漂移特征被误杀、99.9% 无出处，可以用同一个统计框架统一处理：**零分布要与候选可交换，判定要区分「不确定」与「等效」，总方差要包含训练端**。第二节的 Z_jk 公式把 BH、经验校准、训练方差和 MDE 合成了一条计算路径，v0.2 的规则正好是它在 μ̂ = σ̂ = 0、R = 1 时的特例。迁移代价也很小：原型只需改权重播种、加训练端重加权，再加一个按层拟合的两参数零分布。
