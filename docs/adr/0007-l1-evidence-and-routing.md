# 0007 L1 采用三类证据、统计可靠性与优先级路由

- 日期：2026-11-11
- 状态：流程确定；统计参数、检验的小样本回退与内部接口待校准/确认；原型待实现。
- 更新：ADR-0001 的 L1 硬筛规则、ADR-0002 的聚合交接面、ADR-0003 下的 OnlineScoreAdapter/报告契约。L2 统计协议仍由 ADR-0006 定义。

## Context

v0.3 仅把分桶平均残差放在 L2 中作描述，L1 主要按单特征 AUC/IV 与缺失率评级，而且只有「通过」进入 L2。该方式可能挡住边际弱但有交互价值、或能识别存量模型偏差的候选。另一方面，分桶 CVR/Bias 看起来不同，也可能来自抽样波动、用户内相关性、模型版本和整体校准差异；统计显著不证明入模增量或因果影响。

## Decision

L1 固定为六步，不训练任何模型：

1. 确定评估口径与预测分语义。
2. 接入候选、成熟标签和可选存量分，检查样本正确性/PIT。
3. 特征画像与固定分桶。
4. 计算质量与稳定性、标签关联性、存量模型分桶偏差三类证据。
5. 评估效应幅度、置信区间、假设检验、多重校正及时间复现。
6. 汇总数据准入与 L2 优先级，生成报告及候选队列。

流程细节、公式、检验与输出契约以[总体方案 3.1](../总体方案设计.md#31-l1-快筛纯统计不训练任何模型)为准。

### 证据与统计边界

- Bias 统一为 `E/O - 1`，正值高估；平均残差为 `(O-E)/W`，正值低估。零实际转化桶不算 Bias 比值，仍可描述残差，但零事件样本的 bootstrap 不足以证明精度。
- 分别检验标签关联、桶内校准、桶间偏差异质性，整体校准偏差单独报告。模型版本、人群结构、预测分校准及采样口径必须一致或预注册分层。
- 标签驱动的分桶/切片采用发现与独立确认，L1 不使用 L2 验证标签。预测分优先 serving 时刻落盘；replay checkpoint 训练截止早于评估窗口。
- 默认按用户聚类估计不确定性。CI 不是 p 值；整体检验与零假设重采样需满足假设，并通过模拟校准。关注幅度、检验集合、通道/批次/桶级校正及时间窗口在批次前冻结。
- 普通逐行置换、裸残差置换和简单的互信息相减不能被无条件解释为增量检验。需要拟合加性模型或候选纠偏模型的步骤属于 L2。

### 数据状态与优先级

| 展示结论 | 数据状态 / L2 优先级 | 行为 |
|---|---|---|
| 阻断 | blocked / deferred | 已确认数据违规，修复重评 |
| 暂缓 | review 或 insufficient / deferred | 核查疑点、补口径或累积成熟样本 |
| 优先进入 L2 | ready / high | 可靠且值得关注的关联或桶间偏差信号优先训练验证 |
| 常规待评 | ready / normal | 预算排队，保留交互/序列专项与随机审计通道 |

弱 AUC/IV、不显著 Bias、业务预期稀疏性和 PSI 高不单独拒绝。存量分缺失仅使偏差通道未评估；分数错误排除对应分数证据，不自动否决候选其他通道。L2 未执行必须写 `not_evaluated`，不能显示无增量。

### 契约变化

- `TargetSpec` 设计增加存量分来源/类型/目标/版本/训练截止/校准层、采样权重，以及 L1 数据切分和统计协议。
- `OnlineScoreAdapter` 扩展按总体方案 6.5；旧 `logit` 映射为 `score + score_type=logit`，与生产接口对接时显式兼容。
- 后端交接从单一 `(bin,pos,neg)` 扩展为加权实际/预期转化统计；聚类 CI 还需用户×桶×时间片统计或同口径重采样结果。单桶总计数不能恢复用户内相关性。
- 报告增加三类证据、分桶表/CI/检验状态、预测分覆盖率、数据状态、优先级、理由及评估指纹。未评估与数值零分开。

## Consequences

- L1 是成本约束下的候选分流，不预设固定过滤率；需测量队列成本与漏检率。常规/专项/审计通道取得的 L2 证据可以进入后续 gate，不要求 L1 曾获 high。
- 模拟与对照需评价完整流程的误报率、检出率和 CI 覆盖率；不同检验的真值分开定义。冗余但相关的特征不是关联性负对照。
- 对 normal 候选按已登记概率随机抽查并执行 L2，记录加权漏检估计及 CI。L2 不是线上真值，只观察通过者的 A/B 结果也不能估计全体候选 recall。
- v0.3 的固定 AUC/IV 拒绝线、正样本硬下限与 199 探针全流程保证被本 ADR 替代。新效应边界、精度、重采样次数、校正配置及审计预算通过模拟和真实数据校准。
- 本次为文档提交。`feval/` 与既有 mock/校准报告仍是 v0.2，不构成新流程验证；实现与验收清单见总体方案 7.4。
