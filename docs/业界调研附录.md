## 1. 单特征区分度与稳定性：风控评分卡体系

- IV（Information Value）、KS、WOE 分桶是信贷风控评分卡的标准单特征工具，分级惯例（IV<0.02 无用 / 0.02–0.1 弱 / 0.1–0.3 中 / 0.3–0.5 强 / >0.5 可疑）出自评分卡方法论（Naeem Siddiqi, *Credit Risk Scorecards*, 2005），为方案 3.1.3 阈值的直接来源。
- PSI（Population Stability Index）阈值 0.1 / 0.25 同样是风控行业惯例，国内信贷与广告团队广泛沿用（阿里云 PolarDB、知乎技术专栏均有公开口径说明）。
- 对标结论：风控只解决「单特征自身」的问题（对应我们的 L1）；「加入模型是否变好」在风控里由评分卡整体 KS/AUC 与变量间相关性近似处理，我们用 L2 消融更严格。

## 2. 特征选择方法论三族

- Filter（互信息、卡方、Fisher 分数）、Wrapper（消融、递归特征消除）、Embedded（L1、树模型 gain importance）三族是教科书分类（Guyon & Elisseeef, *An Introduction to Variable and Feature Selection*, JMLR 2003；中文综述见《微电子学与计算机》特征选择综述 2022）。
- 对标：**L1 快筛 = Filter 族；L2 消融 = Wrapper 族**；importance 属 Embedded，用于上线后审计而非前置判定。

## 3. 交叉特征：显式交叉与自动搜索

- 显式交叉模型系：FM（Rendle, ICDM 2010）、FFM、DCN（Wang et al., ADKDD 2017）、xDeepFM（Lian et al., KDD 2018）、AutoInt（Song et al., CIKM 2019）——交叉在模型内部学习，无法回答「该不该为它造显式交叉特征」。
- **AutoCross**（Wang et al., KDD 2019）：面向表格数据的自动特征交叉，beam search 生成候选 + 逐个用 XGBoost 的 gain 增量评估。方案 3.4 的「候选生成 → 快筛 → 增量」三段式即其分步离线版；全量 beam search 属于算力更重的变体，列二期评估。
- Friedman H-statistic（Friedman & Popescu, Ann. Appl. Stat. 2008）度量特征交互强度，作 L2 解释备选工具。

## 4. 序列特征：行为序列建模与前置近似

- DIN（Zhou et al., KDD 2018）引入 target attention：候选广告对用户行为序列做注意力加权——证明「序列与候选的相关性」是序列信息量的主要来源，方案 3.3 的 target-aware 统计（命中次数/最近命中位置/时间加权命中）即其免训练近似。
- DIEN（AAAI 2019）、SIM（CIKM 2020）进一步引入兴趣演化与长序列检索，均以训练深度模型为前提，前置评估阶段不可负担，故方案采用统计代理 + pooling 探针 + 条件互信息三层递进。
- 防泄漏：序列快照必须早于样本时间戳，与 Point-in-Time Correctness（Feature Store 标配概念）一致。

## 5. AutoFE（自动特征工程）

- **AutoCross**（同 §3）。
- **OpenFE**（Tian et al., KDD 2023）：候选生成 + 两阶段剪枝 + successive halving，声称超越专家水平；适合作为挖掘模块的候选生成器备选。
- **Featuretools**（MIT，开源）：deep feature synthesis 按实体关系自动堆叠聚合变换，对应方案 4.2 的「关联侧聚合」规则的自动化版本。
- LLM 辅助特征工程（2023–2024 研究方向）：按长期项目「先建模后 Agent」原则后置。
- **Slice Finder**（Chung et al., ICDE 2019）：自动找出模型表现显著变差的数据切片，是方案 4.4 误差驱动挖掘的切片手段。

## 6. Feature Store 与特征生命周期

- Uber **Michelangelo Palette**（Hermann & Del Balso, 2017/2018 公开分享）：首个大规模企业实践，确立「离线/在线一致、特征共享复用」。
- **Tecton**（2020，前 Uber 团队）、**Feast**（Gojek/Google，2019 开源）、**Hopsworks**：现代 Feature Store 三代表，生命周期相关标配能力 = ingestion validation（写入校验）、drift monitoring（PSI/KL/JS 分桶漂移）、training-serving skew 检测、特征版本与血缘。
- 对标：方案 5.2 上线 gate ≈ ingestion validation 的入模强化版；5.3 日 PSI ≈ drift monitoring；5.4 下线三条件为业界少有公开细案的部分，属自研判据（importance 分位 + 消融 + 冗余），Tecton/Hopsworks 文档仅提供「下线需谨慎、需血缘影响分析」的原则性表述。
- 监控开源实现可参考 Evidently（分桶漂移报告）、Arize（特征监控 SaaS）的指标口径。

## 7. 增量价值评估工具箱

- Permutation importance（Breiman, 2001）：打乱单特征看性能下降，无需重训但会高估相关特征组；用于审计参考。
- SHAP（Lundberg & Lee, NeurIPS 2017）：单预测级归因，聚合后可看特征级贡献；计算贵，作解释备选。
- **消融 + paired bootstrap CI**（方案 3.2.2 主采用）：最贴近「加/去该特征」的真实因果问题，代价是每组候选两次训练——这正是 L1 先砍 80% 候选的原因。
- 条件互信息：免模型估计「在已有特征之上」的信息增量，用于序列特征第三层。
- **Poisson bootstrap**（Chamandy et al., Google, 2012）：每个单元独立抽 Poisson(1) 权重来近似多项式重采样，适合在分布式系统里逐行生成；方案 3.2.2 以口径卡的分组键为单元使用，即聚类 bootstrap。
- **ZILN**（Wang et al., 2019）：LTV 预测的零膨胀对数正态损失，评估采用归一化 Gini 与十分位图；是方案 3.1.4 连续型指标族的参照。
